[Node.js] 异步错误处理与优雅退出

发表于 2022-10-30 分类于 Node.js Disqus：

线上 Node.js 服务最怕“看起来还活着，但已经不能正确处理请求”。错误处理不仅是捕获异常，还包括记录上下文、停止接收新请求和安全释放连接。

错误分为可预期与意外

参数错误、资源不存在属于可预期错误，可以返回明确状态码；空指针、连接池损坏属于意外错误，需要记录完整堆栈，并评估是否重启进程。

异步路由统一交给错误中间件

每个异步入口都必须把 rejected Promise 交给统一处理层。日志至少包含请求 ID、路径、状态码和错误堆栈，但不能记录令牌与密码。

响应后不要再次写入

错误中间件先检查 res.headersSent。若响应头已经发送，应把错误交回框架默认处理，避免出现 “headers already sent”。

优雅退出

收到部署平台的终止信号后，先停止接收新连接，再等待进行中的请求完成，最后关闭数据库和消息队列连接。
