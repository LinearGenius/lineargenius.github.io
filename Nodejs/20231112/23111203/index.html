[Node.js + TypeScript] 组织一个可扩展的后端项目

发表于 2023-11-12 分类于 Node.js Disqus：

TypeScript 能检查类型，却不会自动带来清晰架构。真正重要的是模块边界：业务代码不应该直接依赖 Web 框架和数据库实现。

按业务模块组织

相比把所有 controller、service 分成大目录，可以按 users、orders 等业务模块组织，每个模块内部再分 controller、service 和 repository。修改一个功能时，相关文件更集中。

类型不能替代运行时校验

HTTP 请求、环境变量和数据库 JSON 都来自运行时，必须校验后才能视为可信类型。不要用 as User 跳过边界检查。

业务错误使用明确类型

统一错误类型让控制器只负责把领域错误映射为 HTTP 响应。

构建与运行分开

开发时使用监听器，CI 中执行类型检查和测试，生产环境只运行编译后的输出。确保构建目录不包含测试文件和源码映射中的敏感路径。
