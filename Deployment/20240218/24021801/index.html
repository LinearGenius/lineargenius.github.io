[GitHub Actions] 自动构建并发布 Docker 镜像

发表于 2024-02-18 分类于 Deployment Disqus：

自动部署的第一步不是登录服务器，而是得到一个可追踪、可重复构建的镜像。工作流应先测试，再构建和发布。

触发条件

Pull Request 只运行检查；合并到主分支可以发布快照标签；正式 release 再发布语义化版本。这样可以避免每次提交都覆盖生产标签。

最小权限

工作流默认只授予所需权限。发布到 GHCR 通常需要 contents: read 与 packages: write。第三方仓库凭据放在 Secrets 中。

标签不可只用 latest

至少保留 commit SHA 标签，出现问题时才能准确回滚。latest 可以作为便利别名，但不能成为唯一版本。

固定第三方 Action

正式项目可将第三方 Action 固定到完整 commit SHA，并定期由依赖更新工具升级，避免标签被意外修改。
