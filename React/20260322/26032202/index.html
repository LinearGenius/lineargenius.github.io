[Slate.js] 封装一个可扩展的 React 富文本编辑器

发表于 2026-03-22 分类于 React Disqus：

从 Slate 的节点与操作模型出发，封装工具栏、快捷键、自定义元素、序列化、粘贴处理和表单接入，形成可维护的编辑器组件。

为什么选择 Slate

Slate 提供可组合的编辑器核心和 React 渲染层，不提供固定的工具栏与文档结构。自由度适合业务编辑器，但意味着团队要自己定义 Schema、插件顺序、序列化协议和升级策略。官方文档仍将其标记为 beta，生产项目应锁定版本并覆盖关键回归测试。

文档模型先于界面

编辑器 value 是 Descendant 节点树。元素节点包含 type 和 children，文本节点保存字符串与 bold 等 marks。先定义稳定的业务模型，再写渲染组件；不要把按钮样式或 DOM 结构直接当作持久化格式。

创建稳定的 Editor 实例

Editor 必须在组件生命周期中保持同一个引用。withReact 提供 DOM 映射，withHistory 提供撤销重做，自定义插件负责覆盖 normalizeNode、isInline 或 insertData。插件顺序要固定并写入测试。

命令层隔离工具栏

工具栏不直接操作 DOM，而是调用 toggleBlock、toggleMark、insertLink 等命令。命令读取 selection，使用 Editor.nodes 判断当前状态，再通过 Transforms 修改节点。这样按钮、快捷键和斜杠菜单可以复用同一行为。

渲染、粘贴与链接安全

renderElement 必须把 attributes 和 children 传给对应元素；renderLeaf 组合文本 marks。粘贴 HTML 时只接受允许的标签和属性，链接协议限制为 http、https、mailto。图片上传先插入带本地 ID 的占位节点，完成后再用 Transforms 更新 URL。

保存与序列化

保存 Slate JSON 能完整保留结构，适合再次编辑；展示端可以把经过版本迁移的 JSON 渲染为 React，而不是把编辑器 HTML 原样注入页面。文档记录 schemaVersion，模型变化时集中迁移旧数据。防抖保存只处理内容变化，不要因 selection 变化反复请求。

受控边界与表单集成

Slate 的 value 更接近 initialValue，直接用外部 props 覆盖内部节点会破坏历史记录。表单层保存最新文档引用，在明确的“加载另一篇文档”动作中重建 editor。校验规则应检查空段落、最大节点数、链接和图片状态。

测试最值得覆盖的路径

测试命令对节点树的变换、normalize 规则的收敛、复制粘贴、中文输入法组合态、撤销重做、序列化往返和历史数据迁移。端到端测试要覆盖光标、选区和键盘快捷键，因为这些行为无法只靠快照证明。
