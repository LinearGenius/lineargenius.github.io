[UX] 讲座笔记：工程师必须了解的 UX 设计

发表于 2020-02-10 更新于 2020-02-14 分类于 UI/UX Disqus：

这篇笔记来自于 2020.2.6 六角学院的在线研讨会，讲者为兽群之心 / Soking，讲者在这一节讲座中分享了设计用户体验时需要掌握的基本原则，并且以丰富的实务经验来回答许多学员的发问。

UX 的起源

用户经验或用户体验（User Experience，UX），一词由美国学者唐·诺曼所提出⋯⋯「用户经验」包含用户与公司的产品与服务互动中的所有面向。—— 维基百科

UX 其实相当程度地根基于认知心理学。美国有名的认知心理学者 Don Norman 可说是 UX 祖师爷，他被邀请进入 Apple，协助 Apple 重视人类如何使用电脑、重视美学。

在以前的时代是由技术主导设计，现在则是设计师研究如何更 user friendly，电脑于是普及化。而当网络蓬勃发展后，UX 开始大量被需要。

Don Norman 创立的公司 Nielsen Norman Group 有提供 UX 培训，公司官网跟 YT 有一些 UX 文章与教学。但是这些 UX 教学都还是偏理论，所以容易看了很多但不知道怎么开始，这也是在台湾学 UX 容易遇到的问题。

不过用户体验应该是所有团队成员的责任，只要把用户需求放在心里，而不是只有商业面、技术面的话，其实就是在做 UX。

产品可用性原则

产品可用性有三个指标：
有效性 (must have)：没有搞定产品就完蛋。例如：电商不能购物、地图不能定位。
效率 (good to have)：没做到会很麻烦。
满意度：没做到会有人不开心，不一定所有人都能满足，需要参考自己产品定位目标。

有效性跟效率之间的选择，应该看客户需要的是什么而提供，并不是追求两个都要有。

想了解网页 UX 更细节的优化建议可以参考 Google 研究员写的 UX Playbook（中文版），里面有列出一些共通的原则，做到的话体验会比较好。

设计思考

欢迎错误，也欢迎不同背景的人贡献想法。
UX 没有一步到位，必须先做出一个东西，测试用户的反应，再赶快改善。

Site Map

规范出页面层级、标明各页面的编号，页面中有共用组件、有要求权限的话也会标明。

用户旅程地图

可以做得简单也可以做得复杂，可以把前中后台、用户场景、商业逻辑都用可视化的方式呈现。
可视化是 UX 设计师很重要的工作，把抽象的事情变具体，也能帮助讨论不要发散。

Wireframe

工程师可以在 Wireframe 上确认规格跟使用流程。

Q & A

Q: 没办法从过去的 UX 案例来预估成效吗？
A: 过去的成功无法代表未来的成功。跟投资买股票一样。

Q: 哪个阶段会开始请工程师？
A: 在第一天就会跟工程师讨论，画出一个边界，确认解决问题到什么程度，这其实是商业模式层次的问题。
UX 会先定义用户角色，接着做用户研究、在线访谈，使用产品的场景、频率、需求、流程，然后把收集到的信息拿去跟客户做讨论。如果发现有些指标适合量化，就会先列出来，提供之后规格的参考。

Q: 请问每一个案子都会做用户测试吗？如果会的话用户测试大约会找多少人测试呢？
A: 依照尼尔森原则，找 5 到 8 个人就能找出 85% 的问题。在做测试时应该追求快速有效的方法，找越多人测试就越旷日费时、成本越高。测试时，也会把时间限缩在 5 到 10 分钟就做完，并会对测试者进行放声思考法，引导他们讲出对特定界面、元素的认知。

Q: 在判断客户的使用情况是否流畅，可否观察用户在按下某个按钮后，过了多久时间才按下设计师所期待的用户的按钮，可以这样来判断吗? （如果很快就按下的话, 可以代表这个设计是符合UX吗？）
A: 我们会设置一个特定的任务，针对一定数量的用户去测他们进行任务的秒数，可以用 GA 查看有些比较久才进行特定任务的人是先去干嘛了。

Q: 请问，目前 UX 设计遇到的大环境威胁有哪些？例如：

  1. 移动设备越做越小，导致能够设计的空间变少
  2. 客户会为了省钱，而直接要求你们做过的案例框架拿来应用，为了不愿多花设计费
  3. 案例越做越多，模仿的竞争者越来越多
  4. 其他？

面对这些，你们是怎么克服的？

A:

  1. 有限制是好的，因为画面小反而塞不了太多东西，Web 画面较大，可以塞的东西就多，业主常常会希望把画面塞得满满的，导致画面臃肿不堪，所以 Web 比 APP 还难设计。
  2. 每个业主的商业模式都不一样，所以不太会拿其他人的来应用。
  3. 市面上越多流畅的产品，越能够带动业界质量提升，所以竞争多是好事。

Q: 有没有案子是在 iPad 上面做相关的测试？
A: 有，但当时客户不想单独测试 iPad，iPad 可以直着看也可以横着看，所以 UI 有把尺寸设计好就没问题。

Q: UI 报价高还是 UX？
A: 如果客户只想做 UI，我们会问他是否有能力自己做出 Wireframe？能做到什么程度？我们在跟客户告知我们的专业能力后，通常客户也愿意让我们同时做 UX 跟 UI。我们现在新客户都不会接只做 UI 的案子。

彩蛋：UI 设计师是否该学 HTML CSS？

讲者认为 UI 设计师应该要碰 HTML CSS，尤其现在案子要 RWD，如果画面都只用绘图软件做，其实设计师会有盲点，会不知道实际画面是怎么变化的。
