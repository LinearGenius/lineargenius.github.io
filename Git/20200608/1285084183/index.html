在工作中学 Git：rebase 指令

发表于 2020-06-08 分类于 Git Disqus：

在进入公司以前，我都是用 git merge 来合并分支；直到进入公司后，团队都是用 git rebase 来合并，一开始很不习惯，到最近我才渐渐习惯这种合并方式，因此想把 rebase 指令适用的场景记录下来，跟大家分享。

什么是 rebase

rebase 是 merge 以外的另一种合并方式，它会取出一连串的 commit，「复制」它们，然后把它们接在别的地方。

跟 merge 的差别在于： merge 会产生额外的 commit 来合并两个分支；而 rebase 则不会有额外的 commit，如果用线图来表示的话，可以看到用 rebase 来合并分支时，线图将会呈现一条直线。

这样一来，我们的 repo 将会有更好看的 commit 记录。

使用目的

我在工作上使用 rebase 的目的是，为了在远端合并时不发生冲突，需要事先让本地端的 feature branch 的前段长得跟 develop branch 一样，而在后段多出自己添加的 commit。

指令

git rebase 要合并的分支

使用情境

feature/add-addon-categories 分支是从 develop 分支分出来的，在该分支做了一些开发后，准备要推到远端、发 PR 给团队成员 code review。在这之前，需要先 rebase 上游分支（develop），确保在远端合并到 develop 时不会发生冲突。

此时，就可以在 feature/add-addon-categories 中下这个指令：git rebase develop

冲突

rebase 的过程中跟 merge 一样可能会遇到冲突，解冲突时一个 commit 要解一次，冲突解完后要依循以下步骤：
git add . ⇒ git rebase --continue ⇒ 下一个冲突 ⇒ 重复。

至于遇到冲突可以怎么解，我就留到之后再分享啦～不然我已经快没梗了

状况题

rebase 完 push 失败，git 提示先 pull

如果你的分支曾经推到远端过，然后中间又 rebase 其他分支，那之后再 push 时，Git 就会叫你 pull 远端下来再推一次。

这是因为 Git 此时判定本地端的内容比远端的内容还旧，所以才会出现这种提示，然而，此时不能 pull，不然代码又会变成旧的！

所以这时候的解法就是要用 git push --force-with-lease ，硬推上去更新远端内容。
