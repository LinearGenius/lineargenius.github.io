[HTTP] 前端开发必须掌握的请求、缓存与连接语义

发表于 2025-02-16 分类于 JavaScript Disqus：

从一次浏览器请求出发，理解 HTTP 方法、状态码、缓存协商、跨域和不同协议版本对前端性能与正确性的影响。

从 URL 到响应：一次请求经过什么

浏览器解析 URL 后会检查缓存、DNS、连接复用和安全策略，再发送请求。HTTP 定义消息的语义，TLS 保护传输内容，HTTP/2 或 HTTP/3 决定消息如何在连接中承载。前端看到的 Fetch API 是这条链路的上层入口。

方法表达意图，不只是接口命名

GET 用于读取，HEAD 只获取响应头，POST 提交处理，PUT 替换资源，PATCH 局部修改，DELETE 删除资源。安全方法不应改变服务器状态；幂等方法重复执行应得到相同目标状态。网络重试必须考虑幂等性，支付创建等操作还要使用业务幂等键。

状态码决定前端分支

2xx 表示请求已被成功处理；304 让浏览器复用缓存正文；400 表示请求本身无效；401 表示缺少有效身份；403 表示身份有效但没有权限；404 表示资源不存在；409 适合表达状态冲突；429 表示请求过多；5xx 表示服务器处理失败。前端不要把所有非 200 响应都归为“网络错误”。

强缓存与协商缓存

Cache-Control: max-age 控制新鲜期，immutable 适合带内容哈希的静态资源；no-cache 允许存储但要求复验；no-store 才是不存储。过期后浏览器可携带 If-None-Match，服务器比较 ETag 并返回 304。HTML 通常短缓存或协商缓存，带哈希的 JS、CSS 和字体可长缓存。

CORS 是浏览器的读取边界

跨源请求是否允许由响应头决定。非简单请求会先发送 OPTIONS 预检。服务端应精确返回允许的 Origin、方法和请求头；携带 Cookie 时不能使用通配符 Origin。CORS 不是身份认证，也不会阻止服务器收到恶意请求。

HTTP 版本变化了什么

HTTP/1.1 依靠多个连接缓解队头阻塞；HTTP/2 在单条 TCP 连接上多路复用并压缩头部；HTTP/3 使用 QUIC，在丢包时避免不同流相互等待。核心方法、状态码和缓存语义保持一致。前端优化应优先减少无效资源、正确缓存和控制优先级，而不是把升级协议当作万能加速。

调试清单

在 DevTools Network 中检查请求方法、状态码、响应时间分段、缓存命中、重定向链、CORS 响应头和协议版本。复现问题时使用“复制为 cURL”，把浏览器策略问题与服务器响应问题分开。
