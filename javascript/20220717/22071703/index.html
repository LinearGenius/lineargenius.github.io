[前端动画] 博客页面渐显效果是怎么实现的

发表于 2022-07-17 分类于 JavaScript Disqus：

进入这个博客时，标题、菜单和正文不会生硬地同时出现，而是按顺序滑入并渐显。这个效果并不是一条 CSS 动画完成的，而是由“初始隐藏、启动入口、任务队列、动画执行、无脚本兜底”五个部分共同完成。

先看完整执行链路

HTML 根容器带有 use-motion 类。CSS 根据这个类把准备参与动画的元素设为透明。DOM 构建完成后，next-boot.js 调用动画模块，模块再依次处理站点标识、菜单、文章内容和侧边栏。

  1. 浏览器解析 HTML，目标元素以 opacity: 0 开始。
  2. DOMContentLoaded 触发 NexT.boot.motion()。
  3. integrator 将多个动画任务按顺序放入队列。
  4. Velocity 执行动画；当前任务完成后调用 integrator.next()。
  5. 最后一个任务结束，页面保持正常可见状态。

第一步：用 CSS 准备初始状态

渐显需要从透明状态过渡到不透明状态，因此主题先隐藏文章块、标题、正文和归档标题：

use-motion 是一个开关。如果不希望启用动画，只需不添加这个类，正文便不会经历透明状态。把选择器限定在这个开关下面，也能避免动画样式污染其他页面。

第二步：在 DOM 就绪后启动

next-boot.js 监听 DOMContentLoaded。此时页面结构已经可以查询，又不必等待图片等资源全部下载，动画能够更早开始。

NexT.boot.motion() 会读取配置中的 motion.enable。只有动画开启时才组装并启动任务队列，因此配置层和执行层保持分离。

第三步：用 integrator 控制顺序

页面不是靠多个 setTimeout 猜测执行时间，而是使用一个很小的队列控制器。每个中间任务在完成时主动通知队列继续：

bootstrap() 执行第一个任务。任务拿到 integrator 后，在动画完成回调中调用 integrator.next()。这样即使设备性能和内容长度不同，下一个阶段也只会在上一个阶段真正结束后开始。

第四步：Velocity 负责渐显和滑入

配置中为不同区域指定了效果：文章块使用 fadeIn，文章头部和正文使用 slideDownIn，归档标题使用 slideLeftIn。postList 收集对应节点，然后交给 Velocity：

stagger: 100 让一组元素错开 100 毫秒开始，形成层次感；drag: true 会调整同组动画的持续时间。真正的“渐显”来自透明度变化，滑动只是额外的位移反馈。

为什么还要 noscript 兜底

如果 JavaScript 被禁用或资源加载失败，元素会永远停在 opacity: 0。因此页面在 noscript 中把透明度恢复为初始值。动画属于增强效果，不能成为阅读正文的前提。

用原生 JavaScript 实现精简版本

现代浏览器可以用 CSS transition 和少量 JavaScript 完成相同思路：

requestAnimationFrame 让浏览器先提交初始样式，再在下一帧添加可见类。若在同一次样式计算中直接添加两个状态，浏览器可能合并更新，看不到过渡过程。

性能与可访问性

  • 优先动画 opacity 和 transform，避免频繁触发布局。
  • 首屏动画保持简短，正文不应长时间不可见。
  • 监听 prefers-reduced-motion，为减少动态效果的用户直接显示内容。
  • 不要在滚动事件中重复启动整页动画。
  • 动画失败时必须恢复可见状态，避免用户面对空白页面。

实现要点

这套实现把职责拆得很清楚：CSS 负责准备状态，启动模块选择时机，integrator 保证顺序，Velocity 执行具体过渡，noscript 保证内容始终可读。理解这条链路后，即使换掉动画库，也能保留清晰、可靠的页面进入体验。
