[JS] 讲座笔记：AJAX 非同步 / Event Queue 详解

发表于 2020-02-24 更新于 2020-03-02 分类于 JavaScript Disqus：

本篇笔记来自 2020.2.19 六角学院线上研讨会，讲者为偷米骑巴哥的 Tommy。在这一次讲座中，Tommy 老师用许多 Demo 示范了非同步行为与 Queue 之间的关系。

Event Queue 事件伫列

JavaScript 是 Single Thread（单执行绪）语言，只用一颗 CPU 运转，一次只能做一件事。但是，计时器（setTimeout）、AJAX、Promise 是属于 Web APIs，不受单执行绪限制，它们会被放到 Queue 中，等待 JavaScript 执行。

因此，整个流程（Event Loop）就像这样：

所有要执行的任务会被放到 Call Stack 里面，JavaScript 的执行绪会逐一执行 Stack 里的任务，当碰上非同步事件时，为了不让程式被这些需要等待的事件卡著，就会继续执行后续的动作。

那这些非同步事件什么时候才能被执行？答案是，它们会在 Queue 中排队，等到 JavaScript 的执行绪把 Stack 的任务都消化完了，才轮到 Queue 中的非同步事件依序执行。

观念重点：非同步事件会被放进排队序列，先进先出。

单执行绪与 Event Queue 的概念可以参照铁人赛：一次只能做一件事情的 JavaScript，有动图更好理解。

这个例子中，setTimeout() 应该在 3 秒后印出 'b'，但结果却是在 5 秒后，排在 'c' 的后面出现，为什么呢？

这是因为，当 3 秒到时，setTimeout() 就已回来 JavaScript 的执行绪了，但在 Stack 中还有 5 秒 while 回圈及 console.log('c'); 还没执行完毕。
因此，当回圈终于跑完时，'c' 接著印出来，而时间早就到了的 'b' 也就紧跟著印出来了。

for 回圈 - 以 Vue 环境为例

透过 debugger 可以在开发人员工具中看到回圈的分解动作，我们可以看到 for 回圈是等所有次数都跑完，数字才渲染出来；而不是像我们所想像的，跑一次回圈就渲染一个数字在画面上。

那么，要如何每跑一次回圈就渲染一次数字？

答案是，可以用 setTiomeiut() 来达成。

为什么用 setTiomeiut() 就能达成呢？

因为 for 回圈一开始没用 setTimeout() 时，只有 for 自己一个任务在 Stack 中；而使用 setTimeout() 后，就变成每跑一次回圈就产生一个存放在 Queue 中的任务，每个 Queue 中的任务又会被依序插入 Stack 中，于是就能一个执行（渲染）完才换成下一个执行（渲染）。

AJAX

传统网页在跟后端捞资料时，流程是这样的：请求 => 回应 => 请求 => 回应；而使用了 AJAX 技术的网页捞取资料的方法，则是在背景送出请求取得回应。

常见底层

  • XMLHttpRequest (可支援 IE 7 以上, jQuery, axios)
  • HTML5 Fetch API (IE 11 以下都不支援)
