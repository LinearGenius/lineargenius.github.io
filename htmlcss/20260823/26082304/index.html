[Web Font] 使用 unicode-range 拆分字体文件

发表于 2026-08-23 分类于 HTML&CSS Disqus：

按真实字符集生成字体子集，并通过多个 @font-face 与 unicode-range 让浏览器只下载页面需要的字形，降低中文字体加载成本。

为什么中文字体需要拆分

一个包含常用汉字、拉丁字母和标点的完整字体可能达到数 MB。直接把它作为单个 WOFF2 会阻塞文本稳定显示，也浪费只访问少量页面用户的流量。字体子集把字形拆成多个文件，unicode-range 告诉浏览器每个文件覆盖哪些码点。

unicode-range 决定是否下载

同一个 font-family 可以声明多次，每条 @font-face 指向不同子集。浏览器扫描页面实际字符；只要某个字符落入范围，就下载对应的整个子集。unicode-range 不会自动裁剪字体文件，src 指向的文件本身也必须只保留相应字形。

先统计真实字符，再设计分片

从文章、导航、错误提示和动态接口中收集字符，规范化后去重。拉丁、数字和常用标点单独做基础片；汉字按常用频率或码点区间拆分；品牌名和首屏固定文案可以做极小核心片。不要只扫描构建时 HTML而遗漏用户内容和运行时文案。

用 fonttools 生成真正子集

pyftsubset 可以按文本或 Unicode 范围保留字形，并输出 WOFF2。保留必要的布局特性和可变字体轴，生成后再用字体检查工具确认 cmap 与字形完整。

自动生成 CSS 清单

构建脚本应同时输出字体文件、内容哈希和 unicode-range 声明，避免文件与范围错配。文件名带哈希并设置长期 immutable 缓存；CSS 或 manifest 记录版本。新增字符时只更新受影响的分片。

加载策略与字体回退

font-display: swap 让回退字体先显示，optional 更偏向性能但可能本次访问不切换。选择度量接近的系统回退字体，并使用 size-adjust、ascent-override 等描述符减少布局偏移。只预加载确定会在首屏使用的核心片，预加载所有分片会失去按需加载价值。

如何验证是否真的省流量

为中文、纯英文和混合页面分别录制 Network，确认未出现字符所在分片不会下载。检查字体请求的缓存头、压缩格式、传输体积和 Layout Shift。清空缓存测试首次访问，再测试跨页面复用；只看 Lighthouse 总分无法发现范围错配。

容易踩的坑

码点范围写对但文件仍是完整字体；拆得太细导致大量请求；动态字符缺失出现豆腐块；不同字重各复制一套巨大分片；预加载与实际 CSS URL 不一致；Service Worker 长期缓存旧字体清单。生产发布应提供字符缺失监控和系统字体兜底。
