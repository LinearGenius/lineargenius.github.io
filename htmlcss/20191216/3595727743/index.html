[CSS] 没有清除浮动，还是没搞清楚元素特性？

发表于 2019-12-16 更新于 2019-12-21 分类于 HTML&CSS Disqus：

昨天在六角学院社团看到有人发问排版问题，因为是我第一次试著替别人 debug 因此特别想记录下来，顺便当作我使用部落格纪录前端学习之路的滥觞。

这位同学的问题是这样的：

「 请问大家，相似的浮动为什么第一张图 submit 会跑掉，在 textarea 结束加 clearfix 才正常（第二张图），第三张就不会？」



我这样回答：

「因为第一张 textarea 没有下 display:block，所以按钮就跟它并排了；而第三张的 input text 都有下 display:block，所以按钮就不会并排。」

<input> 跟 <img>，display 预设都是 inline-block，也就是说如果不指定为 block，排完它的宽度后，如果还有空间，底下非 block 的元素或浮动元素就会跑上来。inline 跟 inline-block 的差别在于，前者不能指定宽高，而后者可以。

第一个图会跑版的原因是因为 <textarea> 没有下 display:block，所以 float 的按钮便与他并排了。
并排之后整个 <form> 加上左边的 <h6> 的宽度后，整体超过了 .faqform，所以才会掉下来。

第二个图里，<textarea> 下面多加了一块 <div>，这个 <div> 的属性是 block ，所以不是因为加了 clearfix，如果把那个 class 去掉，只留下 <div>，也会有同样效果。如此，接下来的按钮便不会前面的原素并排，整个 <form> 加上左边 <h6> 的宽度后也还在 .faqform 的极限内，版型就正常了。

第三个图版型正常的原因，也是因为前面的元素加了 block，而且整个 .form 加上左边 <h4> 的宽度后还在 .faqform 的极限内。

此外，盒模型的概念也是很重要，子元素要注意宽度加起来是否会超过包住它的父层， 不然一旦内容宽度超过就一定会跑版了。
